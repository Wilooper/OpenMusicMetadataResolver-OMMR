# Credential-free Boyfriend regression — 2026-10-16

Query: `{"artist":"Karan Aujla","title":"Boyfriend"}` via `POST /v1/query`.

Built the current Go server and started it from a new temporary directory with a fresh disk cache. Removed all inherited `OMMR_*` environment variables, explicitly selected a private test configuration, disabled credential-directory discovery with `credentials_dir: ""`, and supplied no env/session file, cookie, bearer or API credentials. Used default 10-second resolution deadline, US Apple storefront and enabled public enrichment. No song-specific IDs or results were hardcoded into implementation.

The HTML pages may be generated by the network/access layer. They do not establish that the upstream services are globally unavailable or that changing API parameters would restore access. Public registrations mean eligible to attempt, not a successful startup connectivity probe.

All seven public identity adapters and two public enrichers started with `credentials: absent`. Qobuz, Tidal, Amazon Music, Pandora, Last.fm, Discogs and AcoustID stayed disabled because credentials were missing. Failed attempts incremented runtime failure counters; immediate cache hits did not issue new provider attempts. Partial-failure positive-cache TTL remains capped at 30 seconds.

## Verification

Live assertions checked credential absence, required-source exclusion, expected accepted IDs, strong identity, identical provider metadata across debug/production, no rejected Apple entities in output, production diagnostic omission and a shared debug cache hit. Native-song fixtures additionally cover separate artists/album/duration, preservation of display extras, exclusion of music-video rows and video fallback for HTML/error/empty music responses. Public Apple requests are tested for storefront handling; anonymous Spotify failures are tested for actionable, body-free errors. Build, vet and the full race-enabled Go suite passed.

## Reproduce

Start from an empty working directory with no credential environment variables. Save a private configuration, select it with `--config`, and keep credential files absent:

```yaml
port: 8080
credentials_dir: ""
cache_provider: disk
cache_dir: ./fresh-cache
provider_timeout: 10s
apple_storefront: us
enable_enrichment: true
```

```sh
chmod 600 test.yaml
/path/to/ommr-server --config test.yaml
# In a second terminal:
curl -sS http://127.0.0.1:8080/v1/query \
  -H 'Content-Type: application/json' \
  -d '{"artist":"Karan Aujla","title":"Boyfriend","debug":true}'
curl -sS http://127.0.0.1:8080/v1/query \
  -H 'Content-Type: application/json' \
  -d '{"artist":"Karan Aujla","title":"Boyfriend"}'
```

Catalog data and origin access can change. The test adds no credentials and does not assert working access to providers that failed.
